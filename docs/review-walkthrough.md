# Review Walkthrough Notes

Notes for the code review exercise in the hands-on GitHub workshop.

## What participants will do

1. Open the pull request **Add review walkthrough notes**.
2. Read through the changed file and find the line that anchors the exercise.
3. Leave their own inline comment on that line.

## What a good review comment looks like

- Point at a specific line, not the whole file.
- Say what you observed and why it matters.
- Suggest a concrete next step.

## Talking points for the demo

- Inline comments are anchored to a line of the diff.
- A comment review is neutral: it neither approves nor requests changes.
- Reviews keep the discussion attached to the code, not buried in chat.
